Binary Search Trees

Balanced BST + operations + DSW

Construct a complete, balanced, binary search tree, using the following values;

A[] = {1, 5, 7, 12, 14, 17, 21, 23, 25, 28, 33, 35, 38, 45, 58 }

Describe the algorithm you used to transform the array into a binary tree.

Redraw your tree after each of the following operations - for each operation explain the algorithm you use to complete it.

  1. INSERT value 15
  2. DELETE value 7
  3. DELETE value 14
  4. DELETE value 35
  5. SEARCH for value 38

Why might you want to balance a binary search tree?

Demonstrate how you could rebalance your tree using the DSW balancing algorithm.

Best exam answer

Construction: choose the middle value as the root. Split the remaining values into left and right halves, then repeat the same middle-value process recursively for each half until no values are left to split. The first root is 23.

Initial balanced BST
INSERT 15
DELETE 7 · leaf
DELETE 14 · one child
DELETE 35 · two children

INSERT 15: 15 < 23 → go left; 15 > 12 → go right; 15 < 17 → go left; 15 > 14 → insert 15 as the right child of 14.

DELETE 7: 7 < 23 → left; 7 < 12 → left; 7 > 5 → right. Find 7 as a leaf node, so delete it directly.

DELETE 14: 14 < 23 → left; 14 > 12 → right; 14 < 17 → left. Find 14 with one child, so promote its child 15 to replace it.

DELETE 35: 35 > 23 → go right and find 35. It has two children, so promote the leftmost node of its right subtree, 38, to replace 35, then remove the original 38.

SEARCH 38: 38 > 23 → go right → 38 is found.

Why balance: after many insertions and deletions, a BST can become very unbalanced. Then search, insertion and deletion may no longer stay near O(log n) and can degrade toward O(n).

DSW

  1. Convert the tree into a right-leaning backbone (vine) using rotations.
  2. Use rotations to compress the backbone back into a balanced tree.
  3. Repeat the compression until the tree is balanced.
Backbone order
1→5→12→15→17→21→23→25→28→33→38→45→58
One valid DSW-balanced result

WHY: This follows the course's middle-element construction, deletion-by-copying convention, and DSW backbone/compression method.

Traversal

Recursive inorder function

void BST<Int>::function1(BSTNode<Int> *p) {
if (p!=0) {
function1(p->left);
print(p->data);
function1(p->right);
}
}

What does the function do? How efficiently does it perform its task?

Compare this with at least 2 alternative approaches.

Show output of this function start from root use your latest tree.

Best exam answer

The function performs a depth-first inorder (LVR) traversal: left subtree → node → right subtree. It visits every node and prints the values in sorted order for a BST. Time complexity is O(n).

Alternative 1 — iterative traversal: use an explicit stack instead of recursion.

Alternative 2 — Morris traversal: temporarily use links/threading so the tree can be traversed without recursion or an extra stack.

Output: 1 5 12 15 17 21 23 25 28 33 38 45 58

WHY: The exact supplied function calls left subtree, prints p->data, then calls right subtree.

Best exam answer

An AVL tree is self-balancing, so it maintains balance automatically during insertions and deletions. Its balance factor is height(left) − height(right) and should stay at −1, 0 or +1. If a node becomes unbalanced, fix that subtree using LL, RR, LR or RL rotations instead of rebalancing the whole tree.

05
Heaps

Max heap + min heap

What is max heap. and give 1 example that we may use max heap.

What is min heap ? and give 1 example that use min heap.

Best exam answer

Max heap: a binary tree where each parent is greater than or equal to its children, so the largest value is at the root. Example: a max-priority queue where the most important item is removed first.

Min heap: a binary tree where each parent is less than or equal to its children, so the smallest value is at the root. Example: an appointment queue where the earliest deadline is removed first.

Best exam answer

Use case: a database containing many customer records or a large number of entries.

SEARCH 52:

[41 66 87]→[48 52 56]→52 FOUND

SEARCH 60:

[41 66 87]→[48 52 56]→[57 58 59]→NOT FOUND

INSERT 7: follow the leftmost path to leaf [2 4 6]. Insert 7 → [2 4 6 7]. The node still has at most 4 keys, so no split.

INSERT 34: go to leaf [28 30 31 32]. Insert → [28 30 31 32 34], so it overflows. Split and promote 31. Parent becomes [8 18 26 31 35], which also overflows; split it and promote 26. Root becomes [26 41 66 87].

DELETE 81: follow the 66–87 branch to [72 78 83], then leaf [79 81]. Delete 81 → [79], which is under half full. Its sibling cannot lend, so combine with the right sibling using separator 83: [79 83 84 85]. Parent becomes [72 78].

07
Multiway Trees

B, B*, B**, B+

In what situation would a B-Tree gain height?

What is the difference between a B-Tree, a B*-Tree and a B**-Tree?

What is a B+ Tree? Briefly discuss the advantage a B+ Tree gives over normal B-Trees.

Best exam answer

B-Tree height: a B-Tree gains height only when the root itself splits and a new root is created.

B / B* / B**: a B-Tree is about half full and splits one full node into two. A B*-Tree is about two-thirds full and splits two nodes into three. A B**-Tree is about 75% full and splits three nodes into four.

B+ Tree: internal nodes act as indexes that guide the search to the actual data stored in the leaf nodes. This allows efficient searching.

WHY: This uses the existing ALGO Week 6 conventions, including the course statement that only a root split increases B-Tree height.

08
Indexes & Tries

Prefix B+ Tree + Trie

What is a Prefix B+ Tree?

What is Trie

Best exam answer

Prefix B+ Tree: a type of B+ Tree that saves space by storing shared prefixes of keys only once.

Trie: a tree that searches using successive parts of a key, such as one character or bit at each level; the path from the root spells the key.
