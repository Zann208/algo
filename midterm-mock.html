Binary Search Trees

Balanced BST + operations + DSW

Construct a complete, balanced, binary search tree, using the following values;

A[] = {1, 5, 7, 12, 14, 17, 21, 23, 25, 28, 33, 35, 38, 45, 58 }

Describe the algorithm you used to transform the array into a binary tree.

Redraw your tree after each of the following operations - for each operation explain the algorithm you use to complete it.

  1. INSERT value 15
  2. DELETE value 7
  3. DELETE value 14
  4. DELETE value 35
  5. SEARCH for value 38

Why might you want to balance a binary search tree?

Demonstrate how you could rebalance your tree using the DSW balancing algorithm.

Best exam answer

Construction: choose the middle value as the root, then recursively choose the middle of each left and right half until every value is placed. The first root is 23.

Initial balanced BST
INSERT 15
DELETE 7 · leaf
DELETE 14 · one child
DELETE 35 · two children

INSERT 15: 15 < 23 → right of 12 → left of 17 → right of 14. Insert at the empty child.

DELETE 7: leaf case; remove it and set its parent pointer to NULL.

DELETE 14: one-child case; its child 15 replaces it.

DELETE 35: two-child copying case; copy the leftmost value of the right subtree, 38, into 35's position, then remove the original 38.

SEARCH 38: 38 > 23 → move right → 38 found.

Why balance: a balanced BST keeps search/insert/delete near O(log n); a badly skewed tree can degrade toward O(n).

DSW

  1. Use rotations to convert the tree to a right-leaning backbone/vine.
  2. Compress the vine with left rotations.
  3. Repeat compression until balanced.
Backbone order
1→5→12→15→17→21→23→25→28→33→38→45→58
One valid DSW-balanced result

WHY: This follows the course's middle-element construction, deletion-by-copying convention, and DSW backbone/compression method.

Recursive inorder function

void BST<Int>::function1(BSTNode<Int> *p) {
if (p!=0) {
function1(p->left);
print(p->data);
function1(p->right);
}
}

What does the function do? How efficiently does it perform its task?

Compare this with at least 2 alternative approaches.

Show output of this function start from root use your latest tree.

Best exam answer

The function performs a depth-first inorder (LVR) traversal and prints every node in sorted order for a BST. Time is O(n); recursive auxiliary space is O(h).

Alternative 1 — iterative stack: use an explicit stack instead of recursion; O(n) time and O(h) extra space.

Alternative 2 — Morris traversal: temporarily restructure/thread the tree and restore it; O(n) time with O(1) extra space.

Output: 1 5 12 15 17 21 23 25 28 33 38 45 58

WHY: The exact supplied function calls left subtree, prints p->data, then calls right subtree.

05
Heaps

Max heap + min heap

What is max heap. and give 1 example that we may use max heap.

What is min heap ? and give 1 example that use min heap.

Best exam answer

Max heap: a binary tree where every parent is greater than or equal to its children; the tree is perfectly balanced with last-level leaves in the leftmost positions, so the largest value is at the root. Example: a max-priority queue.

Min heap: the reverse heap rule: every parent is less than or equal to its children, so the smallest value is at the root. Example: a calendar/appointment queue where the earliest deadline is removed first.

Use case: a large disk-based database, because a B-Tree stores many keys per node and reduces disk seeks.

SEARCH 52:

[41 66 87]→[48 52 56]→52 FOUND

SEARCH 60:

[41 66 87]→[48 52 56]→[57 58 59]→NOT FOUND

INSERT 7: follow the leftmost path to leaf [2 4 6]. Insert 7 → [2 4 6 7]. The node still has at most 4 keys, so no split.

INSERT 34: go to leaf [28 30 31 32]. Insert → [28 30 31 32 34], so it overflows. Split and promote 31. Parent becomes [8 18 26 31 35], which also overflows; split it and promote 26. Root becomes [26 41 66 87].

DELETE 81: follow the 66–87 branch to [72 78 83], then leaf [79 81]. Delete 81 → [79], which is under half full. Its sibling cannot lend, so combine with the right sibling using separator 83: [79 83 84 85]. Parent becomes [72 78].

07
Multiway Trees

B, B*, B**, B+

In what situation would a B-Tree gain height?

What is the difference between a B-Tree, a B*-Tree and a B**-Tree?

What is a B+ Tree? Briefly discuss the advantage a B+ Tree gives over normal B-Trees.

Best exam answer

B-Tree height: a B-Tree gains height only when the root itself splits and a new root is created.

B / B* / B**: a B-Tree is at least about half full. A B*-Tree is about two-thirds full and delays splitting by redistributing first, then splitting two full nodes into three. A B**-Tree pushes the occupancy requirement to about 75%.

B+ Tree: internal nodes are indexes while all actual data values are stored in leaves. The leaves are linked, so ordered/range traversal can move through the leaves without repeatedly visiting internal levels.

WHY: This uses the existing ALGO Week 6 conventions, including the course statement that only a root split increases B-Tree height.

08
Indexes & Tries

Prefix B+ Tree + Trie

What is a Prefix B+ Tree?

What is Trie

Best exam answer

Prefix B+ Tree: a B+ Tree whose internal index nodes store only enough of each key prefix to distinguish between branches. Shorter index keys allow more keys and pointers per node.

Trie: a tree that searches using successive parts of a key, such as one character or bit at each level; the path from the root spells the key.
