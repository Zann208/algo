Week 7

Graphs

Vertices, edges, and the algorithms that walk, measure and connect them.

Graph
A graph G = (V, E) is a nonempty set of vertices V together with a possibly empty set of edges E that connect pairs of vertices.
Remember: vertices = nodes, edges = connections.
Directed Graph (Digraph)
A directed graph is a graph in which every edge has a direction, so the edge from vi to vj is different from the edge from vj to vi.
Multigraph and Pseudograph
A multigraph allows two vertices to be joined by more than one edge. A pseudograph is a multigraph that also allows an edge from a vertex to itself.
Weighted Graph
A weighted graph is a graph in which each edge has a value, such as a distance or a cost.
Complete Graph
A complete graph is a graph in which every pair of vertices is joined by an edge.
Path
A path is a sequence of edges that leads from a vertex v1 to a vertex vn.
Circuit
A circuit is a path that returns to its starting vertex without repeating an edge.
Cycle
A cycle is a circuit in which all the vertices are different.
Order: path → circuit (back to start) → cycle (no repeated vertex).
Adjacency List
An adjacency list stores, for each vertex, the list of vertices that are directly connected to it.
Adjacency Matrix
An adjacency matrix is a |V| × |V| table in which entry (i, j) records whether vertex i is connected to vertex j (or the weight of that edge).
Graph Traversal
Graph traversal visits every vertex of a graph once, marking vertices as visited so that cycles do not cause an infinite loop.
Depth-First Search (DFS)
Depth-first search follows one neighbour as deep as possible before backtracking, and is implemented with recursion or a stack.
Memory: deep first, stack.
Breadth-First Search (BFS)
Breadth-first search visits all the neighbours of a vertex before moving on to their neighbours, and is implemented with a queue.
Memory: level by level, queue.
Shortest Path
The shortest path between two vertices of a weighted graph is the path with the smallest total edge weight.
Dijkstra's Algorithm
Dijkstra's algorithm finds the shortest paths from one start vertex to all other vertices by repeatedly selecting the unchecked vertex with the smallest current distance and updating the distances of its neighbours.
Key fact: start = 0, all others = ∞. It does not work with negative edge weights.
WFI Algorithm
The Warshall–Floyd–Ingerman algorithm finds the shortest paths between all pairs of vertices by testing, for every pair, whether a route through an intermediate vertex is shorter.
Key fact: three nested loops over the vertices, so O(|V|³).
Cycle Detection
A cycle is detected during depth-first search when an adjacent vertex has already been visited and the edge to it is not one of the traversal edges.
Union-Find
Union-find keeps track of disjoint sets using two operations: find, which reports the set an element belongs to, and union, which merges two sets.
Use: testing whether two vertices are already connected, as in Kruskal's algorithm.
Spanning Tree
A spanning tree of a connected graph is a subgraph that connects all the vertices and contains no cycle.
Key fact: it always has |V| − 1 edges.
Minimum Spanning Tree (MST)
A minimum spanning tree is a spanning tree whose total edge weight is the smallest possible.
Kruskal's Algorithm
Kruskal's algorithm builds a minimum spanning tree by sorting the edges by weight and repeatedly adding the smallest edge that does not form a cycle, until the tree has |V| − 1 edges.
Memory: smallest edge anywhere, skip cycles.
Prim's Algorithm
Prim's algorithm builds a minimum spanning tree by starting from one vertex and repeatedly adding the cheapest edge that connects a vertex in the tree to a vertex outside it.
Memory: one tree that grows; cheapest edge leaving it.
Topological Sort
Topological sort orders the vertices of a directed graph of tasks so that the required order between tasks is respected; it repeatedly finds a minimal vertex, numbers it and removes it with its edges.
Network
A network is a directed graph with one source (no incoming edges), one sink (no outgoing edges) and a capacity on every edge.
Eulerian Trail and Eulerian Cycle
An Eulerian trail is a route that includes every edge of a graph exactly once. An Eulerian cycle is an Eulerian trail that is also a cycle.
Key fact: Eulerian cycle ⇔ every vertex has even degree. Eulerian trail ⇔ exactly two vertices of odd degree.
Chinese Postman Problem
The Chinese Postman problem asks for the shortest closed walk that traverses every edge of a graph at least once.
Hamiltonian Cycle
A Hamiltonian cycle is a cycle that passes through every vertex of a graph. A graph with at least one Hamiltonian cycle is a Hamiltonian graph.
Key fact: all complete graphs are Hamiltonian. Euler = every edge; Hamilton = every vertex.
Travelling Salesman Problem (TSP)
The travelling salesman problem asks for the shortest Hamiltonian cycle, that is, the shortest tour that visits every city.

Week 10

Intelligent Agents & Search

What an agent is, what kind of world it works in, and how it searches for a solution.

Agent
An agent is anything that perceives its environment through sensors and acts upon that environment through actuators.
Percept and Percept Sequence
A percept is the input an agent receives at a given instant. A percept sequence is the complete history of everything the agent has perceived.
Rational Agent
A rational agent is one that does the right thing, choosing the action expected to make it most successful according to its performance measure.
Depends on: performance measure, prior knowledge, available actions, percept sequence.
Performance Measure
A performance measure is an objective test of an agent's success, set by the designer.
Rule: base it on what is wanted in the environment, not on how the agent is expected to behave.
Rationality vs Omniscience
Rationality maximises expected performance, whereas perfection (omniscience) would maximise actual performance, which is impossible to guarantee.
Autonomy
An autonomous agent learns from its own percepts to improve its behaviour, instead of relying only on the prior knowledge given by its designer.
Fully vs Partially Observable
An environment is fully observable if the agent's sensors can access the complete relevant state at each point in time; otherwise it is partially observable.
Deterministic vs Stochastic
An environment is deterministic if its next state is determined entirely by the current state and the agent's action; otherwise it is stochastic.
Strategic: deterministic except for the actions of other agents.
Episodic vs Sequential
In an episodic environment each decision is independent of previous decisions; in a sequential environment the current decision can affect future decisions.
Static vs Dynamic
A dynamic environment can change while the agent is deciding; a static environment waits for the agent to act.
Semidynamic: the environment does not change but the agent's performance score does.
Discrete vs Continuous
A discrete environment has a limited number of distinct percepts, actions and states; a continuous environment has a continuous range of them.
Single-Agent vs Multi-Agent
A single-agent environment contains one agent; a multi-agent environment contains several, which may be competitive or cooperative.
Simple Reflex Agent
A simple reflex agent chooses its action using only the current percept, ignoring the percept sequence.
Model-Based Reflex Agent
A model-based reflex agent keeps an internal model of the environment, updates it with each percept, and chooses its action from that state and its rules.
Goal-Based Agent
A goal-based agent chooses actions by considering its goal, using search and planning to reach a desired future state.
Utility-Based Agent
A utility-based agent chooses actions using a utility function that measures how desirable each state is, so it can compare different ways of reaching a goal.
Learning Agent
A learning agent can operate in an initially unknown environment and improves its behaviour from experience.
Goal Formulation
Goal formulation identifies the goal states, the set of states in which the goal is satisfied.
Problem Formulation
Problem formulation decides which states and actions are worth considering for reaching the goal.
Uninformed Search
An uninformed search explores the search tree with no information about where the goal is; it can only generate successors and test for a goal state.
Breadth-First Search (as a search strategy)
Breadth-first search expands every node at one level before moving to the next level, using a FIFO queue.
Cost: memory is the problem, O(b^(d+1)).
Uniform-Cost Search
Uniform-cost search always expands the cheapest step first; when all steps cost the same it behaves like breadth-first search.
Depth-First Search (as a search strategy)
Depth-first search expands the deepest node in the current branch first, using a LIFO stack.
Risk: low memory, but it may never finish on an unbounded branch.
Depth-Limited Search
Depth-limited search is depth-first search with a fixed depth limit l, which removes the possibility of an infinite search.
Iterative Deepening DFS
Iterative deepening depth-first search repeats a depth-limited search with the limit increasing by one each time (0, 1, 2, …) until the goal is found.
Cost: O(b^d); never generates nodes below the goal.
Bidirectional Search
Bidirectional search runs one search forwards from the start state and one backwards from the goal state until the two meet.
Heuristic Function
A heuristic function returns an estimate of how close a state is to the goal, which guides the search towards promising directions.
Greedy Best-First Search
Greedy best-first search expands the node that the heuristic estimates to be closest to the goal.
Risk: false starts and loops, like depth-first search.
A* Search
A* search ranks each node by the cost of reaching it plus the estimated cost from it to the goal: f(n) = g(n) + h(n).
Hill Climbing
Hill climbing is a local search that repeatedly moves to a neighbouring state with a better value and stops when no neighbour is better.
Problem: it can stop at a local maximum.
Simulated Annealing
Simulated annealing is a local search that shakes the state, strongly at first and then more gently, so that it can escape local maxima.

Week 12

Adversarial Search, Game Theory & Probability

Planning against an opponent, and deciding under uncertainty.

Game Theory
Game theory is the study of multi-agent environments in which the actions of one agent affect the outcomes of the other agents, either cooperatively or competitively.
Game (in AI)
A game is a deterministic, turn-taking, two-player, zero-sum environment with perfect information.
Zero-sum: the final utilities are equal and opposite (+1 / −1).
Initial State
The initial state is the starting board position together with an indication of whose move it is.
Successor Function
The successor function returns the list of legal moves from a state together with the state each move produces.
Terminal Test
The terminal test determines whether a state is a terminal state, that is, whether the game is over.
Utility Function
A utility function is an objective function that gives a numeric value to a state; for terminal states of a game this could be −1, 0 or 1.
Game Tree
A game tree is a tree whose nodes are game states and whose branches are the alternating moves of the players.
Minimax Algorithm
The minimax algorithm chooses the move that maximises the worst-case outcome, assuming the opponent always plays optimally.
Cost: time O(b^m), space O(bm).
Optimal Strategy
An optimal strategy is one that leads to an outcome at least as good as any other strategy when playing against an infallible opponent.
Alpha-Beta Pruning
Alpha-beta pruning removes branches of the game tree that cannot affect the minimax decision, because a better choice is already available higher up the tree.
Cost: about O(b^(d/2)) with good move ordering.
Heuristic Evaluation Function
A heuristic evaluation function estimates the value of a non-terminal position from weighted features, so that the search can be cut off before the end of the game.
Horizon Effect
The horizon effect occurs when a search is cut off just before a bad outcome, so the bad outcome lies beyond the horizon of the search and is not seen.
Utility Theory
Utility theory represents an agent's preferences between states by measuring how useful each state is.
Decision Theory
Decision theory combines probability theory and utility theory to choose between actions under uncertainty.
Formula: decision theory = probability theory + utility theory.
Maximum Expected Utility (MEU)
The principle of maximum expected utility states that a rational agent chooses the action with the highest utility averaged over all possible outcomes of that action.
Random Variable
A random variable is a variable whose value is uncertain; it may be Boolean, discrete or continuous.
Atomic Event
An atomic event is one particular combination of values for all the random variables.
Prior Probability
A prior (unconditional) probability is the degree of belief in a proposition when no other information is available.
Joint Probability
A joint probability gives the probability of a combination of values of several random variables; the full table of joint probabilities sums to 1.
Conditional Probability
A conditional probability P(a | b) is the probability of a given that b is known to be true.
Product Rule
The product rule states that P(a ∧ b) = P(a | b) · P(b) = P(b | a) · P(a).
Independence
Two variables are independent if knowing the value of one does not change the probability of the other.
Bayes' Law
Bayes' law states that P(b | a) = P(a | b) · P(b) / P(a), so one conditional probability can be calculated from the reverse conditional and two unconditional probabilities.

Week 13

Data Compression

Short codes for frequent symbols, long codes for rare ones.

Data Compression
Data compression encodes data using fewer symbols or bits, so that it takes less space to store and less time to transfer.
Codeword
A codeword is the sequence of code symbols that represents one symbol of the message.
Prefix Property
A code has the prefix property if no codeword is a prefix of any other codeword, so a message can be decoded without any look-ahead.
Code Optimisation Rule
In an optimal code a less likely symbol never has a shorter codeword than a more likely one: if P(mi) ≤ P(mj) then L(mi) ≥ L(mj), and no short code is left unused.
Huffman Coding
Huffman coding is a method that builds a prefix-free code from symbol frequencies, giving the most frequent symbols the shortest codewords.
Method: repeatedly join the two lowest-frequency nodes; left = 0, right = 1.
Huffman Tree
A Huffman tree is a binary tree in which every symbol is a leaf, every internal node holds the sum of its children's frequencies, and the path from the root gives each symbol's code.
Adaptive Huffman Coding
Adaptive Huffman coding builds and updates the Huffman tree while the data is being read, so the symbol frequencies do not need to be known in advance.
Key fact: one pass; encoder and decoder update the tree in the same way.
Run-Length Encoding
Run-length encoding replaces a run of repeated symbols with a count and a single copy of the symbol.
Limit: it does not work if the data itself contains numbers.
